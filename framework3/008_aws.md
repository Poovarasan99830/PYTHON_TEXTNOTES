EC2                = Rental Computer

Instance           = Room in a Hotel
                   = You can choose small, medium, or luxury rooms (instance types based on CPU/RAM).

                   = Run server for 2 hours → pay only for 2 hours.

                    == Increase or decrease servers anytime based on traffic.

VPC (Virtual Private Cloud)

VPC = unga own private network inside AWS
Internet-la oru private area create pannitu, anga unga servers run pannradhu



Real-world analogy
   Think of a gated community 🏘️
     
     Full city = Internet
     Gated community = VPC
     Houses = EC2 instances

    👉 Outside ellarum access panna mudiyadhu
    👉 Only allowed people dhaan enter pannuvaanga



VPC la enna components irukkum?

1. Subnet
2. Internet Gateway (IGW)
3. Route Table
4. Security Group
5. Network ACL (NACL)


How it works (Flow)
Neenga VPC create pannuveenga
Subnets create pannuveenga
IGW attach pannuveenga
Route table configure pannuveenga
EC2 launch pannuveenga

👉 Ippo unga own network ready ✅


Real-time example
   Neenga oru company app build panreenga:
     
     Frontend → public subnet (users access)
     Database → private subnet (secure 🔐)
     
     👉 Idhu safe architecture


Why VPC important?
  🔐 Security control
  🌐 Network isolation
  🎯 Full customization
  🏢 Enterprise-level setup


Important
   👉 Without VPC → everything open → risk 😓
   👉 With VPC → controlled access ✅

Security Group = firewall for your EC2 server
               =Yaaru server-ku varalam, yaaru varakoodadhu nu control pannum


Real-world analogy
    Think of apartment security gate 🚪

    Security guard check pannuvaar
    Allowed person → inside
    Unknown person → block ❌

   👉 Idhu dhaan Security Group


Why Security Group use pannuvom?
  Server open-a vechaa danger ⚠️
  
  Internet-la yaar venaalum try pannuvaanga:
     Hack pannalaam
     Data steal pannalaam
     Server crash pannalaam

  So control venum → adhan Security Group


Real-world analogy
   Neenga veedu kattineenga 🏠
       👉 Door lock illama vechaa:
              Yaar venaalum ulle varalaam ❌

       👉 Door + lock vechaa:
              Only allowed people dhaan varuvaanga ✅

       👉 That lock = Security Group


Real Example
   Website run pannreenga:
   👉 You allow:
          Port 80 → users access
          Port 22 → only your IP
   👉 Result:
         Website works ✅
         Hackers blocked ❌


Main Reasons:
   1. 🔐 Security
   2. 🎯 Control
   3. 🚫 Attack prevention
   4. 🌐 Traffic filtering

Storage na enna EC2-la?
  Storage = unga server data store panna space
  Files, OS, database, logs ellam enga save aagudhu = storage


🏠 Real-world analogy
Think of cupboard / hard disk 💾
    Small cupboard → few items
    Big cupboard → more items
    👉 Idhe maari EC2-ku storage size decide pannuvom

Main Storage Types in EC2
    1. EBS (Elastic Block Store)
         👉 Most important ⭐
         Hard disk madhiri
         OS + app install inga dhaan
         Persistent (server stop pannalum data irukkum)
        👉 Example:
           C drive in laptop

    2. Instance Store
         Temporary storage
                Server stop/terminate → data delete 😓
                Fast but risky

        👉 Example:
               RAM / temporary files
    
    3. EFS (Elastic File System)
        👉 Shared storage
                Multiple servers share pannalam
                Like network drive

SSH na enna?
  SSH (Secure Shell) na remote server-ah (EC2) secure-ah connect pannra method



🏠 Real-world analogy
     Think of remote control 🎮
     TV unga veetla irukku
     Neenga vere place-la irukeenga
          👉 Remote use panni control pannuveenga
    👉 Idhe maari:
         SSH = remote control for your server

Why “Secure”?

Data encrypt aagum 🔒
Username/password illa → key pair use pannuvom
Hack panna romba kashtam

⚙️ How SSH works?
      EC2 create pannumbodhu → key pair create pannuveenga
      Private key (.pem) unga kitta irukkum
      Public key → server-la store aagum
      SSH connect pannumbodhu → key verify pannum

      👉 Match aana → login success ✅

SSH = unga laptop-lendhu server-ah remote-ah control panna secure way
SSH = secure remote login method for servers


SSH access by port numer 22
Important
Port 22 open irukkanum (Security Group)
.pem file safe-ah vechukkanum
Share panna koodathu ❌


What you can do after SSH?
Install software
Run commands
Deploy project
Manage server full control 💪
